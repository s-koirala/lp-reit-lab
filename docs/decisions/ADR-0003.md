# ADR-0003: Front-end architecture — React static SPA + precomputed Python artifacts + TS deterministic-DCF mirror

- **Status:** Accepted
- **Date:** 2026-06-05
- **Deciders:** SKIE (user decision; research-backed, 8 parallel research agents across two rounds)
- **Supersedes:** [ADR-0002](ADR-0002.md) — **interactive-screener portion only** (Streamlit). ADR-0002's Quarto report, free-OSM-tile, and DRY shared-engine decisions remain in force.
- **Related:** [methodology memo](../methodology/methodology_react-merge_2026-06-05.md), [ADR-0001](ADR-0001.md), [research memo](../research_notes/research_market-scoping_2026-06-05.md)

## Context

ADR-0002 chose Streamlit as the interactive screener. In practice the Streamlit UI
is visually clunky (notably the sidebar "wall of sliders") and does not meet the
presentation bar for a published research product. A separately-commissioned
Lovable-generated React app (`north-side-property-compass`: React 19 + TanStack
Start/Router + shadcn/ui + Tailwind v4 oklch tokens + Recharts) has a strong,
polished aesthetic but only mock, magic-number analytics. The goal is to merge the
rigorous, tested Python engine (`src/lp_reit_lab/finance`, plus a forthcoming
forecasting / Monte-Carlo layer) into the beautiful React app, and add property
search and a retrospective + projection time-series feature.

Four hard constraints make the integration non-trivial:

- **(a)** the tested Python engine must remain the **single source of truth** — no
  loose math reimplementation;
- **(b)** the reproducibility contract requires Python-side ReproLogs (git HEAD,
  pip freeze SHA-256, dataset checksums, RNG seed, model hash) for every
  artifact-producing run;
- **(c)** hosting is free/open **static** (Cloudflare Pages, per ADR-0002 and the
  publishing rules);
- **(d)** the forecasting layer (statsmodels VECM / state-space, arch bootstrap,
  Monte-Carlo) is **Python-only and heavy**.

A four-thread research pass (design principles; assumption-control UX;
shadcn/Recharts/map implementation; integration architecture) established the
decisive facts: `statsmodels` and `arch` are **absent from the Pyodide 0.29.4
lockfile** (cannot run in-browser); Cloudflare Python Workers cap **128 MB / 10 ms
CPU** (cannot run the forecasting libs); free Python API tiers (Render, Hugging
Face Spaces) **sleep with 30–50 s cold starts** (breaks the static + snappy model);
and the deterministic DCF is **pure arithmetic** — trivially portable and
parity-testable.

## Decision

Adopt a **hybrid static architecture**, cut along the deterministic/statistical seam
(*deterministic DCF is cheap, portable, and needs live interactivity; forecasting/MC
is expensive, non-portable, and does not need live recompute*):

- **Front-end:** the vendored React app (now `web/` in this repo) is the product UI.
  Keep its shadcn/Tailwind-v4/oklch design system; **replace its magic-number
  `computeMetrics`** with the parity-gated TS mirror below.
- **Build-time (full Python venv):** the tested engine + forecasting + Monte-Carlo
  run offline under the 13-field ReproLog and emit **versioned static artifacts** —
  `per_property_metrics.json`, `scenario_grid.parquet` (DCF/IRR over the 3–4
  dominant assumptions), `forecast_dist.parquet`, `mc_summary.json`, and
  `golden_vectors.json`. Each artifact is stamped with its `run_id` for closed-loop
  provenance.
- **Client deterministic recompute:** a **TypeScript mirror of only** the
  deterministic functions in [metrics.py](../../src/lp_reit_lab/finance/metrics.py)
  and [cashflow.py](../../src/lp_reit_lab/finance/cashflow.py) gives instant slider
  interactivity. Forecast bands and Monte-Carlo fans are **rendered from precomputed
  artifacts, never recomputed client-side.**
- **Parity gate (CI):** the Python engine *generates* `golden_vectors.json` (the
  language-agnostic contract; neither language owns it); pytest and Vitest both
  assert against it with a relative tolerance (`rtol`) set from the observed
  cross-runtime residual — not a magic epsilon. Vectors must include the edge cases
  the engine encodes: zero-rate amortization, the cash-flow-negative
  exit-cap→appreciation reversion fallback, and the multiple-IRR-root stream (rank
  by NPV there). Any divergence fails the build. **The TS mirror is a
  conformance-gated derivative, not a second source of truth.**
- **Repo:** the React front-end is consolidated **into this repo** under `web/` so
  the engine, golden vectors, artifacts, ReproLogs, and front-end share one
  governed provenance boundary.
- **Hosting:** static **Cloudflare Pages**. No hosted Python API, no Pyodide
  forecasting. A localhost FastAPI / stlite tool may exist for the researcher's own
  exploration but is **never** a dependency of the published site.

## Consequences

- (+) Single Python source of truth preserved; the TS mirror is conformance-tested
  to it, and the forecasting layer has no TS counterpart to drift.
- (+) Reproducibility contract intact — all heavy computation stays in the venv
  where `emit-repro-log` fires; the `run_id` stamped into each served artifact
  closes the provenance loop.
- (+) Stays on free static Cloudflare Pages; no always-on server, no cold-start
  jank, no serverless surface to secure.
- (+) Beautiful, accessible UI (the P1 design-system pass) on a rigorous engine.
- (−) No live recompute of *arbitrary* assumptions: the client recomputes the cheap
  deterministic DCF, but forecasting/MC distributions are fixed per build —
  mitigated by a precomputed scenario grid over the dominant assumptions.
- (−) Dual-language parity becomes a maintained CI obligation (golden-vector
  cross-tests in pytest + Vitest).
- (−) The React app retains a Lovable **build** coupling
  (`@lovable.dev/vite-tanstack-config` wires the Nitro/Cloudflare target; dev-only
  `lovable-tagger`). The runtime telemetry sink (`lovable-error-reporting.ts`) and
  `.lovable/` metadata are removed in **P0**; the build-config decoupling is a **P1
  follow-on**, deferred to avoid breaking the static build.
- (−) Artifact regeneration on every data/model change adds a build step (the
  Python "artifact compiler").

## Alternatives considered

- **Pyodide / WASM in-browser Python:** stays static, but `statsmodels` and `arch`
  are absent from the Pyodide 0.29.4 lockfile — the forecasting layer cannot run —
  and the core is a 200 MB-class, multi-second first-load tax. Rejected for
  forecasting.
- **Live Python API (FastAPI):** Cloudflare Python Workers cap 128 MB / 10 ms (can't
  run the libs); Render free spins down after ~15 min (30–50 s cold start); HF
  Spaces free sleeps after 48 h; Railway/Fly aren't free long-term. Breaks the
  static model and adds an always-on surface. Rejected as the hosted path;
  acceptable only as a localhost dev tool.
- **Full TypeScript port of the engine:** fastest UI, but a second source of truth,
  guaranteed math drift, and impossible to reproduce statsmodels/arch numerics in
  TS. Rejected. Only the *cheap deterministic* subset is mirrored, parity-gated.
- **Restyle Streamlit (status quo):** Streamlit has aesthetic ceilings the user
  explicitly rejected; does not reach the published-product bar. Rejected.
